【共通前提 — このプロジェクトの鉄則】
- リポジトリ: Vite + Three.js のボクセルゲーム。ソースは src/game/parts/*.js（番号順に結合され
  src/game.generated.js が生成される。生成物は絶対に手で編集しない。npm run assemble で再生成）。
- 関数宣言はモジュール全体でホイストされるためファイル番号をまたいだ呼び出しは可。ただし
  トップレベル実行時の変数参照は定義順（番号順）に注意。
- 検証コマンド: npm.cmd run check（assemble+vite build）。これが通ることは最低条件で、十分条件ではない。
  必ず npm.cmd run dev のプレビューを実ブラウザで開き、機能を操作して確認する。
  プレビュータブがバックグラウンドだと rAF がスロットルされ時間系が止まって見えるので、計測は
  フォアグラウンドで行う。window.__mcDbg（82-weather-and-loop.js 末尾）にテスト用フックが多数ある。
  新機能には必ず __mcDbg にテストフックを追加し、その使い方を成果報告に書くこと。
- ブロック追加の定番フロー: 20-textures.js にCanvasテクスチャ（+末尾normalMapリスト）→
  22-block-types.js に TYPES エントリと const → 53-inventory.js の ITEM_DEFS →
  55-crafting.js の RECIPES → 52-raycast.js（硬さ BLOCK_HARDNESS / 適正ツール blockPreferredTool /
  ツール制限 requiredToolTier / ドロップ blockDrops）。
- 非立方体形状は TYPES[type].model（{box:[x0,y0,z0,x1,y1,z1]} / {kind:'cross',...}）。
  当たり判定は collisionBoxes / collisionHeight。メッシュ描画はメインスレッド(34-mesh-rebuild.js)と
  Web Worker(src/world-mesh-worker.js)の両方に同じ結果が出るよう実装し、
  メッシュ出力が変わったら 34-mesh-rebuild.js の MESH_WORKER_VERSION を +1 する。
- ブロック編集の永続化は必ず setEdit() 経由（edits.set 直呼び禁止）。構造物生成は put/air 経由

【今回のタスク C5】

【目的】松明・ランタン・溶岩などの発光ブロックから光をBFS伝播させ、本家の「松明で照らす」体験を
完成させる。動的PointLight方式(12-lights.js/PLACED_LIGHTS)からライトマップ方式へ置き換える。

【対象ファイル】src/world-mesh-worker.js / 34-mesh-rebuild.js / 12-lights.js / 52-raycast.js /
22-block-types.js / 82-weather-and-loop.js

【仕様】
1. 発光ブロック定義: TYPES に lightLevel を追加（松明14、ランタン15、提灯14、発光結晶13、
   溶岩15、かまど(点火)13、TNT?なし、ポータル系は後続タスク）。ワーカーへのペイロード
   blockModels と同様に lightLevels 表を渡す。
2. skylight(C4)と同じ配列に blocklight チャンネルを追加（別Uint8Arrayまたは上位4bit/下位4bitパック）。
   光源セルに lightLevel を置き、全方向BFSで-1減衰。頂点カラー = max(skylight係数×昼夜, blocklight)
   になるようシェーダ入力を設計（実装簡略化のため、頂点カラーを2アトリビュート(sky,block)にし、
   mkMat の onBeforeCompile で `light = max(sky * dayFactor, block)` を計算する。dayFactor は
   uniform で毎フレーム更新）。onBeforeCompile が複雑すぎる場合の代替: 頂点カラー1本に
   max(sky×現在昼夜, block) を焼き、昼夜変化時に「見えているチャンクを数秒かけて順次再メッシュ」
   でもよいが、性能とちらつきに注意（推奨は uniform 方式）。
3. 増分更新: ブロック設置/破壊時、影響半径15ブロック内のチャンク（最大3x3）を再メッシュキューへ。
   既存の requestEditedBlockRebuild の仕組みを使う。ライトは再計算でよい（差分伝播までは不要）。
4. 12-lights.js の PLACED_LIGHTS の PointLight 生成は廃止し、互換のためレジストリだけ残す
   （スポーン抑制がC7で light 値参照に切り替わるまで既存ロジックを壊さない）。
5. MESH_WORKER_VERSION +1。

【受け入れ条件】
- 真っ暗な洞窟に松明を置くと半径14の光が距離減衰つきで広がる（スクショ）
- 松明を壊すと周囲が暗く戻る（数フレーム以内）
- 夜の地上で松明・ランタン・かまどの明かりが本家らしく見える
- 昼夜の移り変わりで屋外は暗く/明るくなるが、松明の光は一定
- FPSが従来から大きく落ちない（高速飛行時のフレーム時間を HANDOFF の計測法で確認）

【テスト方法】F4で洞窟→松明設置/破壊。夜(setTime)の村の明かりを確認。
__mcDbg.lightAt を blocklight 対応に拡張。

【禁止事項】共通前提に同じ。動的PointLightの追加禁止。既存の太陽光/環境光の全体設計を壊さない。

【本家準拠 数値リファレンス — 上の本文と数値が食い違う場合はこちらを優先する】

- 光源ブロックの光レベル表（本家準拠）:
  松明14 / ランタン15 / 提灯14(独自) / 発光結晶13(独自) / 溶岩15 / かまど(点火)13 /
  グロウストーン15(C16で追加) / ネザーポータル11(C16) / レッドストーントーチ7(C15) /
  レッドストーンランプ15(C15) / エンチャントテーブル7(C11) / 醸造台1(C16) / 火15(あれば)
- 伝播: 全6方向へ1ブロックごとに-1。不透明ブロックで遮断。水中も伝播する(追加減衰なし)。
- 最終輝度 = max(スカイライト × 昼夜係数, ブロックライト) を 0.8^(15-L) で輝度化。
  ブロックライトは昼夜の影響を受けない(松明は昼も夜も同じ明るさで、夜に目立つだけ)。
