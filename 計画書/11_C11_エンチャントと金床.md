【共通前提 — このプロジェクトの鉄則】
- リポジトリ: Vite + Three.js のボクセルゲーム。ソースは src/game/parts/*.js（番号順に結合され
  src/game.generated.js が生成される。生成物は絶対に手で編集しない。npm run assemble で再生成）。
- 関数宣言はモジュール全体でホイストされるためファイル番号をまたいだ呼び出しは可。ただし
  トップレベル実行時の変数参照は定義順（番号順）に注意。
- 検証コマンド: npm.cmd run check（assemble+vite build）。これが通ることは最低条件で、十分条件ではない。
  必ず npm.cmd run dev のプレビューを実ブラウザで開き、機能を操作して確認する。
  プレビュータブがバックグラウンドだと rAF がスロットルされ時間系が止まって見えるので、計測は
  フォアグラウンドで行う。window.__mcDbg（82-weather-and-loop.js 末尾）にテスト用フックが多数ある。
  新機能には必ず __mcDbg にテストフックを追加し、その使い方を成果報告に書くこと。
- ブロック追加の定番フロー: 20-textures.js にCanvasテクスチャ（+末尾normalMapリスト）→
  22-block-types.js に TYPES エントリと const → 53-inventory.js の ITEM_DEFS →
  55-crafting.js の RECIPES → 52-raycast.js（硬さ BLOCK_HARDNESS / 適正ツール blockPreferredTool /
  ツール制限 requiredToolTier / ドロップ blockDrops）。
- 非立方体形状は TYPES[type].model（{box:[x0,y0,z0,x1,y1,z1]} / {kind:'cross',...}）。
  当たり判定は collisionBoxes / collisionHeight。メッシュ描画はメインスレッド(34-mesh-rebuild.js)と
  Web Worker(src/world-mesh-worker.js)の両方に同じ結果が出るよう実装し、
  メッシュ出力が変わったら 34-mesh-rebuild.js の MESH_WORKER_VERSION を +1 する。
- ブロック編集の永続化は必ず setEdit() 経由（edits.set 直呼び禁止）。構造物生成は put/air 経由
  （world.set 直呼び禁止）。セーブは 33-save-state.js の統合 SAVE（mc_save_<seed>）。
  新フィールドは必ず「無ければデフォルト」で読み、既存セーブを壊さない。
- 【絶対禁止】60-rave-venues.js / 70-music.js（音楽会場）、music/、gikopoi2/、hallucinate/ の変更。

【今回のタスク C11】

【目的】XPの使い道を作る。簡易エンチャントと、修理/合成の金床。

【対象ファイル】20-textures.js / 22-block-types.js / 53-inventory.js / 55-crafting.js /
56-inventory-panel.js / 52-raycast.js / 33-save-state.js

【仕様】
1. エンチャントテーブル: レシピ=本1(本=紙3+革1、紙=サトウキビ…が無いので簡略: 本棚/本はC14で
   追加する「本」を使う。C14未実装なら本アイテムを本タスクで先行追加、レシピ=板材3+革1→革は
   C12で牛から。依存が未実装の間は __mcDbg.give で検証)+ダイヤ2+黒曜石4。
   右クリックでUI(既存コンテナUIの雛形を流用): 対象ツール/武器/防具スロット+3択ボタン
   (コスト1/2/3レベル)。選択肢は簡易テーブルから抽選:
   効率I-III(採掘速度+30%/段)、耐久I-III(耐久消費を1/(1+段)確率でスキップ)、
   ダメージI-III(+1.25/段)、防護I-III(軽減+8%/段)、火属性I(攻撃で炎上)、無限I(矢を消費しない)。
   周囲の本棚数(半径2)で高コスト枠が解放される(0冊=Lv1のみ、15冊=Lv3まで)。
2. エンチャント効果の適用: アイテムに ench 配列を持たせ(スロットのitemオブジェクトに追加、
   セーブ互換に注意)、採掘速度(52)/戦闘(39)/防具軽減(51)/弓(39)の計算に反映。
   アイテム名表示に「効率 II」等を付記し、アイコンに紫の枠。
3. 金床: レシピ=鉄ブロック3+鉄インゴット4。UI: 素材2スロット+出力。同種ツール2つ→耐久合算+12%、
   またはツール+素材(鉄ツールに鉄等)で耐久50%回復。コスト=1-3レベル。エンチャントは
   高い方を引き継ぐ(競合は先勝ち)。
4. どちらのブロックも設置/破壊/ドロップ/硬さを既存フローで登録。

【受け入れ条件】
- 本棚で囲んだテーブルでLv3エンチャントが出る。効率IIIのダイヤツルハシで石の採掘が明確に速い
- 耐久/ダメージ/防護/火属性/無限が各系統で機能する(実測)
- 金床で耐久合成と修理ができ、エンチャントが引き継がれる
- エンチャント付きアイテムがセーブ/リロードで保持される。旧セーブも読める

【テスト方法】__mcDbg に enchant(slot, id, lvl) を追加して全効果を強制付与テスト。
UI経由の抽選も3回以上実測。

【禁止事項】共通前提に同じ。ラピスラズリ消費・エンチャント本・つるはし以外への幸運などは実装しない。

【本家準拠 数値リファレンス — 上の本文と数値が食い違う場合はこちらを優先する】

- 本棚: テーブルの周囲2ブロック(同じ高さ〜+1)に最大15冊で効果最大。
  0冊=最上段の要求レベル約8 / 15冊=最上段の要求レベル30(冊数で線形に上げる)。
- 3択スロット: 表示された要求レベル以上のとき選択でき、消費レベルはスロット位置ぶん(1/2/3)。
  (本家1.8以降の方式。要求レベルと消費レベルは別物であることに注意)
- 効果の数値(本家準拠):
  効率N: 採掘速度に N²+1 を加算 / 耐久N: 耐久消費が発生する確率を 100/(N+1)% に /
  ダメージ増加N: +0.5×N+0.5 / 防護N: 被ダメージ-4%×N(装備合計の上限64%) /
  火属性N: 命中時 4×N 秒炎上 / 射撃ダメージ増加N: 矢ダメージ×(1+0.25×(N+1)) /
  無限: 矢を消費しない(矢を1本以上所持している必要あり)。
- 金床: 合成後の耐久 = 両者の残耐久合計 + 上限の12%(上限まで)。
