## 進め方（3ステップ）

1. **発注**: 上記モデルの**新しいチャット（新規セッション）**を開き、この文書の下にある「▼▼▼」から最後までを**全部コピーして**貼り付け、送信する。
2. **検収**: 「実装完了」の報告が来たら、下の【検収チェック】を自分で実施する。
3. **出荷**: 全部合格ならコミット＆push。不合格なら【うまくいかない時】を見る。

## 検収チェック（あなたがやる合格判定）

- [ ] コピペ部分にある【受け入れ条件】を、実際にゲームを遊んで1つずつ確認した

## うまくいかない時（期待した品質に達しない場合）

- **受け入れ条件を満たしていない** → 文例:「受け入れ条件『◯◯』が未達です。実際に動かして確認してから修正してください」
- **動くけど本家Minecraftっぽく見えない** → 本家のスクリーンショットを貼り、「この見た目に寄せてください」と具体的な違い（暗さ・形・色など）を指摘して差し戻す。往復は2〜3回まで。
- **関係ない所が壊れた** → 文例:「◯◯が壊れました。今回の変更が原因です。修正するか、無理なら今回の変更をすべて取り消してください」
- **会話が迷走してきた** → そのセッションは見捨てる。新しいセッションで「未コミットの変更をすべて元に戻して」と頼み、git status で戻ったことを確認してから、この手順書をもう一度最初から発注する。※ git clean は自分のファイルまで消えるので使わない。
- **同じモデルで2回失敗** → Claude Opus 4.8 に切り替えて、同じコピペ文で再発注する。

【共通前提 — このプロジェクトの鉄則】
- リポジトリ: Vite + Three.js のボクセルゲーム。ソースは src/game/parts/*.js（番号順に結合され
  src/game.generated.js が生成される。生成物は絶対に手で編集しない。npm run assemble で再生成）。
- 関数宣言はモジュール全体でホイストされるためファイル番号をまたいだ呼び出しは可。ただし
  トップレベル実行時の変数参照は定義順（番号順）に注意。
- 検証コマンド: npm.cmd run check（assemble+vite build）。これが通ることは最低条件で、十分条件ではない。
  必ず npm.cmd run dev のプレビューを実ブラウザで開き、機能を操作して確認する。
  プレビュータブがバックグラウンドだと rAF がスロットルされ時間系が止まって見えるので、計測は
  フォアグラウンドで行う。window.__mcDbg（82-weather-and-loop.js 末尾）にテスト用フックが多数ある。
  新機能には必ず __mcDbg にテストフックを追加し、その使い方を成果報告に書くこと。
- ブロック追加の定番フロー: 20-textures.js にCanvasテクスチャ（+末尾normalMapリスト）→
  22-block-types.js に TYPES エントリと const → 53-inventory.js の ITEM_DEFS →
  55-crafting.js の RECIPES → 52-raycast.js（硬さ BLOCK_HARDNESS / 適正ツール blockPreferredTool /
  ツール制限 requiredToolTier / ドロップ blockDrops）。
- 非立方体形状は TYPES[type].model（{box:[x0,y0,z0,x1,y1,z1]} / {kind:'cross',...}）。
  当たり判定は collisionBoxes / collisionHeight。メッシュ描画はメインスレッド(34-mesh-rebuild.js)と
  Web Worker(src/world-mesh-worker.js)の両方に同じ結果が出るよう実装し、
  メッシュ出力が変わったら 34-mesh-rebuild.js の MESH_WORKER_VERSION を +1 する。
- ブロック編集の永続化は必ず setEdit() 経由（edits.set 直呼び禁止）。構造物生成は put/air 経由
  （world.set 直呼び禁止）。セーブは 33-save-state.js の統合 SAVE（mc_save_<seed>）。
  新フィールドは必ず「無ければデフォルト」で読み、既存セーブを壊さない。
- 【絶対禁止】60-rave-venues.js / 70-music.js（音楽会場）、music/、gikopoi2/、hallucinate/ の変更。

  既存キーバインドを奪わない。npmパッケージの追加も禁止（three固定）。

【今回のタスク S1】

【目的】ゲームの「外装」を本家らしく整える。タイトル画面・ポーズ画面・操作ヘルプの文言と
軽量なDOM/CSSを担当する。

【対象ファイル】index.html / src/game/styles.css / C18が集約した文言オブジェクト
(実装済みなら該当ファイル、未実装なら overlay 部分)

【仕様】
1. タイトル画面: ゲーム名(例:「MINECRAFT WEB — 和風ワールド」等、ユーザーに確認)、
   スプラッシュ的な一言、操作の要約(WASD/マウス/E/Tab/Q/Shift/Ctrl/数字/F3系デバッグ)。
2. ポーズ画面: 再開/設定/(あれば)タイトルへ戻る、操作一覧の全表。
3. 初回プレイ向けチュートリアルトースト文言10個程度(例:「木を殴って丸太を集めよう」
  「E でインベントリ。2x2で作業台が作れる」…進行に沿った順)。表示ロジックは実装済みの
   進捗HUD(59-progress.js)の目標文を流用してよい。文言のみ差し替え。
4. トーンは日本語・です/ます無しの本家風簡潔文。ゲームロジックのJSは変更禁止。
   文言はすべて1つのオブジェクト/セクションに集約し、開発者が差し替えやすくする。

【受け入れ条件】タイトル/ポーズ/ヘルプが実画面で崩れず表示され、npm.cmd run check が通り、
console error/warn ゼロ。全キー表記が実装と一致していること(54-input.js を読んで裏取りする)。

【禁止事項】ゲームロジック・キーバインド・音楽会場関連(R T Y U I O P [ Z X C V J K L M)の
文言変更は現状維持で記載のみ。innerHTML への未サニタイズ挿入禁止。
