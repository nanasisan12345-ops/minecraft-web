# 計画書の使い方（まずこれを読む）

このフォルダには手順書が22個入っています。**基本は番号順に、1つずつ**進めます。
1つの手順書 = 1回の発注 = 1コミット = 1push です。

## あなたがやることは3つだけ

1. **発注** — 手順書に書いてあるモデルの新しいチャットを開き、手順書の「▼▼▼」から下を全部コピペして送信
2. **検収** — 完了報告が来たら、手順書の【検収チェック】を自分で実施（10分程度）
3. **出荷** — 合格ならコミット＆push → GitHub Pages で実機確認 → 次の番号へ

不合格のとき・品質が出ないときの対処は、各手順書の【うまくいかない時】に書いてあります。

## 品質が期待に達しないときの共通ルール

1. **まず差し戻し**: 「受け入れ条件『◯◯』が未達」と具体的に指摘して同じセッションで修正させる（2〜3往復まで）
2. **2回失敗したら格上げ**: Codex既定 → Codex推論最高 → Claude Sonnet 5 → Claude Opus 4.8 の順に切り替え、同じコピペ文で新規セッションから再発注
3. **Opusでも失敗したら**: タスクを分割（「仕様の1と2だけ」）するか、別モデルにdiffレビューさせて指摘リストを添えて再発注
4. **壊れたら**: 新しいセッションで「未コミットの変更をすべて元に戻して」と頼む（git clean は使わない）

## 時間・利用枠が足りなくなったら

優先順位: **ライト(01〜03) ＞ 水(08〜09) ＞ XP(10〜11) ＞ ネザー/エンド(15〜16) ＞ 残り**
ライトと水だけでも「本家に近い」体感が最も大きく変わります。
